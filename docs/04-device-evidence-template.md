# OpenRator — device-pass evidence template (M5.4/M5.5/M5.6)

**Preferred workflow (M5.4 pipeline):** copy
[`device-run.example.json`](device-run.example.json) to `docs/device-run.json`,
replace every measurement and evidence cell with the real device results, then
run `cd apps/mobile && npm run evidence:init`. That validates the cold/warm
budgets, the ≥ 72 h crash-free soak, both devices, and the release identity, and
renders `docs/04-device-evidence-<date>.md` directly.

You can also copy this file manually to a dated working copy and fill it in.
Either way, link the completed copy from [`04-qa-checklist.md`](04-qa-checklist.md).
The automated portion is already enforced in CI; this template captures only the
🟡 rows that need a physical device or real management account.

Grounding: spec §11, [`04-qa-acceptance.md`](04-qa-acceptance.md) (generated by
`npm run acceptance`), [`04-qa-checklist.md`](04-qa-checklist.md).

## 3. M5.4 device flow script

Per device, in order:

1. Fresh install → onboarding (paste key, management toggle) → Home populated.
2. Spend tab: management key → standard key → airplane mode (stale badge).
3. Providers catalog: search, sort, status links.
4. Policy: toggle one provider, reopen the tab, confirm read-back on the dashboard.
5. Keys: create → reveal → copy → test → collapse → revoke.
6. Clear stored key → restart → onboarding shown again.

Record any deviation and whether it reproduced on the second device.
